# 本机视觉模板包格式

`vision-core` 从指定目录读取本机 PNG 模板，不进行网络访问。每张模板必须是 8 位 RGB 或 RGBA PNG，尺寸不超过 1024 × 1024。透明像素按白色背景合成。模板应从用户获准使用的目标界面中裁出牌面或按钮，保持相同的裁剪边界和皮肤，不要加入昵称、房间号等个人信息。原始截图与本机模板默认放在 Git 忽略的 `.local-test-data/` 内。

目录结构：

```text
template-pack/
  tiles/
    1m.png ... 9m.png 0m.png
    1p.png ... 9p.png 0p.png
    1s.png ... 9s.png 0s.png
    1z.png ... 7z.png
  actions/
    none.png
    chi.png
    pon.png
    kan.png
    riichi.png
```

`m`、`p`、`s` 分别代表万、筒、索；`z` 代表字牌；`0m`、`0p`、`0s` 为赤五。加载器要求 37 张牌图和 5 种按钮状态全部存在，避免缺少类别时误报。`none.png` 是无按钮状态的代表画面。识别返回每个候选的置信度和不确定槽位；任意槽位不确定时，整组手牌或按钮结果都不会作为确定结果提交。

当前仓库只含代码生成的合成测试图案，没有可分发的雀魂模板或模型。首次使用、浏览器缩放变化、不同皮肤和行动按钮的实际识别精度，须由本机真实截图测试确认。完整模板包的制作与授权仍是 v0.0.1 的未完成项。

## 在便携程序内采集本机模板

打开雀魂对局，点击“找窗口”并校准手牌区域。在浮窗输入框中按画面从左到右输入当前 13 或 14 张手牌牌码，再点击“学习模板”；程序只截取已校准的手牌区域，逐张裁出牌面并保存到便携包旁的 `models/template-pack/tiles/`。已有同名牌图不会被覆盖。画面与输入牌数不一致、出现第五张同种牌或牌槽检测失败时不保存。

采集按钮时，在输入框输入 `@chi`、`@pon`、`@kan`、`@riichi` 或 `@none`，点击“学习模板”，然后在目标窗口上框选对应按钮或无按钮背景。按钮图保存在同目录下的 `actions/`，同样不会覆盖已有文件。每次成功学习后，当前识别会停止；完整 37 张牌图和 5 种按钮图齐备后，点击“开始”重新加载本机模板。此流程需要用户自行核对标签和画面；完成模板采集也不等于识别准确率验收通过。

如果点击“开始”时模板包尚不完整，浮窗会显示可读取的牌图数和按钮图数，例如 `牌图 11/37、按钮 1/5`。损坏或非 8 位 RGB/RGBA PNG 不计入数量。

开发时还可用 Rust 示例 `cargo run -p vision-core --example learn_tiles --locked -- <RGB 文件> <宽> <高> <模板包目录> <13或14张牌码>` 离线采集；发布包无需 Rust 或 Python 环境，应用内的“学习模板”按钮提供相同的手牌采集能力。

本机诊断可用 `cargo run -p vision-core --example inspect_tiles --locked -- <RGB 文件> <宽> <高> <牌图目录>` 检查候选数、最高分标签和默认置信度门槛。`scripts/probe-vision-tiles.ps1` 可在提供真值手牌后记录截图和牌图哈希、候选标签及是否通过默认门槛；结果保存在被 Git 忽略的 `.local-test-data/runs/`。牌图目录可只包含当前诊断所需的合法牌码 PNG；这些命令不会将截图或牌图复制进仓库。正式运行仍要求上面列出的完整模板包。单张样例的最高分正确不代表达到可自动推荐的置信度。

行动按钮区域可用 `cargo run -p vision-core --example inspect_actions --locked -- <RGB 文件> <宽> <高> <按钮图目录>` 在本机诊断。`scripts/probe-vision-actions.ps1` 接受一个正例和若干反例，记录各输入与模板哈希，要求正例检出预期动作、反例均为空。按钮图目录可只含要验证的类别；诊断输出检出的动作、位置、相似度与匹配耗时。正式运行依然要求完整按钮模板与真实画面验收。
