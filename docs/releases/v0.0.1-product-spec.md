# Riichi Screen Helper v0.0.1 开发文档

## 1. 项目概述

### 1.1 推荐仓库名

实际仓库：`mahjong-screen-helper`

名称直观表达了项目用途：识别日麻屏幕牌面，并通过浮窗提供辅助建议。后续加入牌效、防守、复盘和多平台适配时仍然适用。

可选名称：

- `mahjong-screen-helper`
- `riichi-overlay`
- `riichi-tile-assistant`

### 1.2 v0.0.1 目标

开发一个 Windows 10/11 x64 上可以直接双击运行的便携程序，第一版限定为：

- 支持雀魂网页版四人标准立直麻将。
- 只读截屏、识牌和透明浮窗推荐。
- 不注入网页、不抓取通信、不自动点击游戏界面。
- 默认完全离线，联网只用于用户手动检查更新。
- CPU 优先，GPU 作为可选加速路径。
- 首次启动通过框选牌桌区域完成校准。
- 自动适配窗口移动、分辨率和 Windows DPI 缩放。
- 输出 Top-3 切牌、向听数、有效牌数、置信度和简短理由。
- 识别吃、碰、杠、立直按钮，并给出是否建议及理由。

雀魂官方利用规约对未经许可的外部程序和可能影响服务的操作存在限制。因此本项目的第一版保持只读和手动操作边界，用户应自行确认目标游戏的最新规则和风险。

## 2. 参考项目与复用边界

以下项目用于调研和架构参考：

- [QueHun](https://github.com/jzjzzzzzzz/quehun)：参考窗口校准、只读分析、牌面状态和安全边界。主代码使用 Apache-2.0。
- [huanlemajiang](https://github.com/tian-xiu/huanlemajiang)：参考 YOLOv8、模板匹配、ROI 校准和 Top-3 推荐流程。
- [Akagi-NG](https://github.com/Xe-Persistent/Akagi-NG)：参考实时动作分析、Rust 推理和立直后 lookahead。项目使用 AGPL-3.0，只作为架构参考。
- [RiichiCam](https://github.com/MMitch42/RiichiCam)：参考端侧 ONNX 识别和本地模型部署。
- [agari](https://github.com/agari-industries/agari)：参考 Rust 牌效、向听、有效牌和规则接口设计。

所有第三方代码、模型、牌图、训练数据和字体必须在仓库中建立许可证清单。AGPL 项目的代码不能直接复制到本项目的闭源发布版本，除非项目明确接受相应的许可证义务。

## 3. 技术方案

### 3.1 总体架构

采用 Rust 核心加 Tauri 或原生 Windows 透明窗口：

```text
Windows 屏幕采集
    ↓
区域校准与图像预处理
    ↓
牌面和按钮识别
    ↓
时间稳定性过滤
    ↓
局面状态机
    ↓
牌效与动作推荐
    ↓
透明浮窗显示
```

### 3.2 模块划分

- `capture`：枚举并锁定雀魂浏览器窗口，优先使用 Windows Graphics Capture，保留 BitBlt 兼容路径。
- `calibration`：用户框选手牌、四家各自副露、牌河、宝牌、行动按钮共八个区域，保存归一化坐标和 DPI 信息。
- `vision`：按牌槽分割图像，模板匹配作为快速路径，小型 ONNX 模型作为复杂画面和低置信度回退。
- `state`：维护摸牌、切牌、吃、碰、杠、立直、和牌、流局等事件。
- `rules`：实现四麻牌效、向听、有效牌、可见牌扣除、鸣牌和立直限制。
- `overlay`：透明置顶、可拖动、可缩放、暂停快捷键和手动纠错。
- `packaging`：发布便携目录和可选安装包，不要求 Python、Node 或 .NET 环境。

### 3.3 识别策略

程序持续低成本扫描配置区域，但只有检测到稳定变化才重新计算：

1. 捕获手牌、动作按钮和必要公共信息区域。
2. 使用牌槽分割减少识别范围。
3. 先使用模板匹配处理清晰稳定的牌面。
4. 对缩放、动画、遮挡或低置信度区域使用小型 ONNX 模型。
5. 连续 3 帧确认牌面稳定后才提交局面变化。
6. 识别结果进入状态机，避免动画过程触发错误推荐。

训练数据先使用公开牌图和现有数据，再采集本机截图进行微调。调试截图必须由用户主动开启，默认不保存原始截图。

## 4. 核心数据接口

视觉层和规则层使用稳定的数据结构隔离：

```rust
struct VisionSnapshot {
    hand: Vec<Tile>,
    open_melds: Vec<Meld>,
    visible_tiles: Vec<Tile>,
    dora_indicators: Vec<Tile>,
    action_buttons: Vec<ActionButton>,
    confidence: f32,
    source_frame_id: u64,
}

struct GameState {
    hand: Vec<Tile>,
    open_melds: Vec<Meld>,
    visible_tiles: Vec<Tile>,
    dora_indicators: Vec<Tile>,
    round_wind: Option<Wind>,
    seat_wind: Option<Wind>,
    riichi: bool,
    phase: Phase,
}

struct Recommendation {
    action: Action,
    rank: u8,
    shanten: i8,
    ukeire: u16,
    confidence: f32,
    reason: String,
}
```

识别置信度不足、牌数不合法或连续帧不稳定时，状态进入 `Uncertain`，暂停推荐并标记待确认牌。用户可以在浮窗中修正牌面后重新计算。

## 5. 推荐逻辑

第一版候选排序按以下顺序执行：

1. 最低向听数。
2. 最大有效牌数。
3. 根据可见牌修正后的实际有效牌数。
4. 保留牌型结构、宝牌和赤宝牌。
5. 在候选接近时给出简短解释。

第一版支持：

- 普通形、七对子、国士无双向听计算。
- 手牌、牌河、副露和宝牌指示牌的可见牌统计。
- Top-3 打牌推荐。
- 吃、碰、杠、立直动作建议。
- 动作建议展示动作前后的向听和有效牌变化。
- 立直后模拟推荐切牌。

防守危险度、完整打点估算、未来多回合搜索和 AI 全局策略不属于 v0.0.1 必须功能。

## 6. 局面状态机

建议状态：

```text
Idle
  ↓
Calibrated
  ↓
HandStable
  ↓
AwaitDiscard / ActionAvailable
  ↓
RecommendationReady
```

任意阶段遇到牌数错误、窗口失焦、画面动画或低置信度时进入：

```text
Uncertain
```

需要处理的事件：

- `Draw`
- `Discard`
- `ChiAvailable`
- `PonAvailable`
- `KanAvailable`
- `RiichiAvailable`
- `RiichiDeclared`
- `RoundEnd`
- `WindowLost`

## 7. 浮窗交互

浮窗默认显示：

- 当前识别出的手牌。
- Top-3 切牌候选。
- 每个候选的向听数和有效牌数。
- 识别置信度。
- 吃、碰、杠、立直建议。
- 当前状态和待确认牌。

交互功能：

- 透明置顶。
- 拖动和缩放浮窗。
- 暂停/恢复识别。
- 快捷键重新识别。
- 点击牌面进行手动纠错。
- 隐藏浮窗但保留后台识别。

程序不执行自动点击，不代替用户选择或确认游戏操作。

## 8. 性能目标

- 稳定画面到浮窗更新：低于 250 ms。
- 冷启动：低于 2 秒。
- 普通 CPU 笔记本可持续运行。
- 运行内存目标：低于 250 MB。
- 识别只处理校准后的局部区域。
- 牌面未变化时不重复运行完整规则计算。

## 9. 发布方式

第一版发布便携目录：

```text
RiichiScreenHelper/
  RiichiScreenHelper.exe
  models/
  assets/
  licenses/
  config/
```

用户直接双击 `RiichiScreenHelper.exe` 使用。程序第一次运行生成配置文件，模型和运行库随程序分发。后续版本可以把模型嵌入单文件执行程序。

## 10. 开发里程碑

### M0：静态截图验证

- 完成区域框选、牌槽分割和默认雀魂牌皮肤识别。
- 建立公开数据与本机截图样本集。
- 验证 100%、125%、150% DPI。

### M1：牌效核心

- 完成向听、有效牌、可见牌扣除和 Top-3 切牌。
- 建立规则单元测试和基准测试。

### M2：实时浮窗

- 接入窗口采集、稳定帧检测、透明浮窗和手动纠错。
- 完成暂停、隐藏、拖动和快捷键。

### M3：动作状态

- 加入吃、碰、杠、立直按钮识别。
- 加入动作前后模拟和理由展示。
- 加入副露、赤宝牌和立直状态跟踪。

### M4：便携发布

- 生成 Windows 便携包。
- 在不同分辨率、DPI、窗口模式和浏览器缩放下回归测试。
- 完成崩溃日志、模型版本和配置迁移。

## 11. 测试计划

### 规则测试

- 普通形、七对子、国士无双。
- 赤五、鸣牌、立直、杠后补牌。
- 可见牌扣除和牌数合法性。

### 视觉测试

- 不同浏览器缩放。
- Windows 100%、125%、150% DPI。
- 窗口移动、全屏、窗口化和动画过渡。
- 低置信度、遮挡、亮暗背景和牌面变化。

### 状态测试

- 摸牌、切牌、连续快速操作。
- 吃、碰、杠、立直。
- 流局、和牌、重新开局和窗口失焦。

### 性能测试

- 连续运行 30 分钟。
- 统计 CPU、内存、端到端延迟和误触发次数。
- 在没有 Python、Node、Rust 或 .NET 的干净 Windows 环境中双击运行。

## 12. v0.0.1 验收标准

- 新用户可以在首次启动时完成区域校准。
- 在已支持的雀魂网页版画面中，可以稳定识别自己的手牌。
- 手牌变化后能在 250 ms 目标内更新推荐。
- 推荐至少显示 Top-3 切牌、向听和有效牌。
- 识别不确定时不会输出未经标记的确定性建议。
- 吃、碰、杠、立直按钮出现时可以识别并显示动作建议。
- 不安装 Python 或其他开发环境即可运行。
- 程序不自动点击、不注入网页、不上传截图。

## 13. 默认假设

- 首版只支持雀魂网页版默认四麻牌桌界面。
- 用户使用单个显示器，并在首次启动时完成校准。
- 用户手动执行所有游戏操作。
- 默认不保存原始截图，调试截图必须主动开启。
- 默认 CPU 推理，GPU 加速作为可选路径。
- 多平台、多游戏、三麻、完整防守和高阶 AI 决策放到后续版本。
